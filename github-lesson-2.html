What's inside a repo?

A repo is just a folder on your computer with a few special parts. Click each one.

Documents / GitHub / dice-game

Click a part of the repo

Each part has a job. Only one of them is yours to write code in.

Key point: the .git folder is where every save point lives. If a student deletes it, the folder stops being a repo. Windows hides it by default, and that's fine.

Which repo names would a real studio use?

Click each name to see how it does.

Naming rules: lowercase, words joined with dashes, no spaces, and say what the game is. Only use your first name in a repo name if you want to, since names can be public.
Fast version: read each name aloud and have students vote thumbs up, sideways, or down before clicking.

Part A: create your repo and publish it

Two places, one repo

Create repository makes the repo on this computer only.

Publish repository makes the matching copy on GitHub.

Until you publish, GitHub doesn't know your repo exists.

Model it: do each step on the projector while students follow. Decide ahead of time whether repos stay private (the default) or public. If they stay private, you can't open them until they add you as a collaborator in Lesson 3.

Part B: add your code, commit, and push

The rule for the whole year

Change files, then commit with a clear message, then push.

If you only commit, your work lives on this one computer. If it's pushed, it's safe on GitHub.

Watch for: students who copy their file somewhere other than the repo folder. If it doesn't appear in the Changes tab, it isn't in the repo. Use Show in Explorer every time.

Your turn: build your repo

15:00
The Commit button is gray

Type a summary. If you did, check that at least one file has a check mark.

My file isn't in the Changes tab

It isn't inside the repo folder. Use Repository, then Show in Explorer, and copy it there.

I don't see Push origin

You haven't committed yet, or you already pushed. Check the History tab.

Done early? Add a "## Controls" section to your README, and a line saying what you want to add next. Commit and push each change.
Circulate: check that each student's GitHub page (Repository, then View on GitHub) shows their code file. That proves the push worked.
